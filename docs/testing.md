# Тестирование (лабораторная 6 — Unit-тесты и TDD)

Тесты лежат в отдельном проекте `tests/ResumeBuilder.Tests` (фреймворк **xUnit**).
Он ссылается только на библиотеку `ResumeBuilder.Core`, то есть проверяется ядро программы
без окон интерфейса.

## Как запустить

* **Visual Studio:** меню «Тест → Обозреватель тестов» → «Запустить все тесты» (зелёный треугольник).
* **Командная строка:** `dotnet test` в корне репозитория.

## Методы «до» и «после» (setup / teardown)

В xUnit нет атрибутов `[SetUp]`/`[TearDown]` как в jUnit — вместо них используются обычные средства C#:

| Что нужно | jUnit | xUnit (у нас) | Пример |
|---|---|---|---|
| перед **каждым** тестом | `@BeforeEach` | конструктор класса тестов | `FileTests()` создаёт новое резюме-пример; `ReportTests()` ставит русский язык |
| после **каждого** теста | `@AfterEach` | `IDisposable.Dispose()` | `FileTests.Dispose()` удаляет файлы, созданные тестом |
| один раз **на весь класс** | `@BeforeAll` / `@AfterAll` | `IClassFixture<T>` | `TestFolderFixture` создаёт временную папку один раз и удаляет её после всех тестов класса |

xUnit создаёт **новый объект класса тестов для каждого теста**, поэтому тесты не влияют друг на друга.

Тесты, которые меняют язык сообщений (`Messages.Culture` — общее статическое поле), объединены
в коллекцию `[Collection("Messages")]`: xUnit не запускает их параллельно, и один тест не может
«переключить язык» посреди другого.

## Исключительные ситуации

Проверяется, что программа на плохих данных выбрасывает **понятное исключение нужного типа**:

```csharp
[Fact]
public void Binary_WrongSignature_ThrowsInvalidData()
{
    // файл с чужой сигнатурой "XXXX" вместо "RSMB"
    var ex = Assert.Throws<InvalidDataException>(() => new BinaryResumeSerializer().Load(path));
    Assert.Contains("не файл резюме", ex.Message);
}
```

## Временные интервалы

Два способа:

1. `Stopwatch` — замеряем время и проверяем, что оно меньше предела
   (`NormalizePhone` 10 000 раз < 1 с, отчёт по 1000 местам работы < 0,5 с, сохранение/загрузка 100 раз < 2 с).
2. `[Fact(Timeout = 30_000)]` — xUnit сам провалит асинхронный тест, если он идёт дольше 30 секунд
   (экспорт в PDF).

Пределы взяты с большим запасом, чтобы тесты не «мигали» на медленной виртуальной машине.

## Пример TDD: проверка повторяющихся навыков

Цикл **красный → зелёный → рефакторинг**:

1. **Красный.** Сначала написан тест `ValidationTests.DuplicateSkill_IsError`: в резюме навыки `C#` и ` c# `,
   ожидается ошибка «Навык «C#» указан несколько раз». Тест не компилировался / падал — такой проверки не было.
2. **Зелёный.** В `ResumeValidator.ValidateManual` добавлен минимальный код: группировка навыков по
   названию без пробелов и регистра (`GroupBy(s => s.Name.Trim().ToLowerInvariant())`), для групп из 2+
   элементов — ошибка. Строка ошибки добавлена в `Messages.resx` и `Messages.en.resx`.
3. **Рефакторинг.** Добавлен второй тест `DifferentSkills_NoDuplicateError` (разные навыки — ошибки нет),
   пустые названия исключены из группировки, чтобы не было двойной ошибки вместе с «название не заполнено».

Так же через тест сначала были зафиксированы граничные случаи возраста (`Age_IsChecked`: родился в 2010 г. — 16 лет, можно;
2020 г. — 6 лет и 1900 г. — больше 100 лет — ошибка) и проверка `null` на входе валидатора (`ExceptionTests.Validate_NullResume_Throws`).
