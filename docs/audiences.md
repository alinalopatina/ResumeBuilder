# Целевые аудитории документации

У проекта три группы читателей. Им нужна разная информация, поэтому документы разделены.

| Аудитория | Что им нужно | Где это лежит |
|---|---|---|
| **Пользователь** (студент, соискатель) | что умеет программа, как установить и запустить, как сделать PDF с QR-кодом, где лежат файлы и журналы | `README.md` (разделы «Что умеет программа», «Что нужно установить», «Сборка и запуск»); в будущем — инструкция к установщику |
| **Разработчик** (кто будет дорабатывать код) | структура решения, как собрать и запустить тесты, правила коммитов и пул-реквестов, описание классов и методов, термины | `README.md` («Структура», «Тесты»), `CONTRIBUTING.md`, `docs/testing.md`, справочник API (DocFX из XML-комментариев), `GLOSSARY.md`, `CHANGELOG.md` |
| **Проверяющий** (преподаватель на защите) | где в коде реализована каждая лабораторная и каждое требование листа задания | `docs/labs.md`, `docs/testing.md`, `docs/docs-audit.md` |

## План размещения информации

1. **README.md** — короткая «входная дверь»: что это, как запустить, ссылки на остальные документы.
   Подробности сюда не копируются, чтобы не было двух разных версий одной инструкции
   (принцип единого источника истины).
2. **CONTRIBUTING.md** — только для разработчиков: как вносить изменения.
3. **CHANGELOG.md** — для всех: что изменилось в версии.
4. **Справочник API** — генерируется из комментариев в коде, поэтому всегда совпадает с кодом.
5. **docs/** — подробные материалы: лабораторные, тестирование, аудит документации.
