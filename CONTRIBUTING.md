# Как внести изменения в проект

Спасибо, что хотите помочь! Ниже — правила, по которым принимаются изменения.

## Подготовка

1. Сделайте форк репозитория или создайте ветку, если у вас есть доступ.
2. Убедитесь, что проект собирается и тесты проходят: `dotnet build` и `dotnet test`.

## Ветки

| Ветка | Назначение |
|---|---|
| `main` | стабильная версия, в неё попадает только проверенный код |
| `feature/<кратко>` | новая функция, например `feature/docx-import` |
| `fix/<кратко>` | исправление ошибки, например `fix/arm64-start` |
| `docs/<кратко>` | только документация |

Напрямую в `main` не коммитим — только через пул-реквест.

## Требования к коммитам

- Один коммит — одно логическое изменение (не смешивать исправление ошибки и новую функцию).
- Сообщение на русском языке, в повелительном или описательном виде, первая строка до 72 символов:
  - хорошо: `Проверка повторяющихся навыков в ResumeValidator`
  - хорошо: `Исправлен запуск на Windows ARM64`
  - плохо: `fix`, `правки`, `ещё изменения`
- Если нужно пояснение — пустая строка после заголовка и затем текст: *что* и *зачем* изменено.
- Не добавлять в коммит папки `bin/`, `obj/`, журналы `logs/` и личные файлы (они в `.gitignore`).

## Пул-реквесты

1. Название — кратко, что сделано; в описании — зачем и как проверить.
2. Все тесты проходят (`dotnet test`), сборка без новых предупреждений.
3. Для новой логики в `ResumeBuilder.Core` — добавлены unit-тесты (лучше написать тест сначала, по TDD).
4. Публичные методы `ResumeBuilder.Core` снабжены XML-комментариями (`summary`, `param`, `returns`, `exception`).
5. Новые строки интерфейса — в файлах ресурсов `.resx` на двух языках, а не прямо в коде.
6. Пользовательские изменения записаны в раздел «Не выпущено» файла `CHANGELOG.md`.
7. Пул-реквест небольшой — проще проверить. Большие изменения лучше разбить.

## Стиль кода

- Стандартные правила именования C#: `PascalCase` для классов и методов, `_camelCase` для закрытых полей.
- Логика — в `Core`, в `Wpf` — только интерфейс и ViewModel (шаблон MVVM).
- Сообщения в журнал — через Serilog с параметрами (`Log.Information("Сохранено {Path}", path)`), а не склейкой строк.
